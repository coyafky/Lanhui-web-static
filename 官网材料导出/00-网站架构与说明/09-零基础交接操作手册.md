# 蓝辉轻改官网｜零基础交接操作手册

> 适用对象：没有编程经验、负责整理资料、提出修改、验收网站的接手人。核对日期：2026-10-24。本文是操作入口；文件逐项说明见 [10-网站文件逐项批注.md](10-网站文件逐项批注.md)，具体任务见 [11-维护模块操作卡.md](11-维护模块操作卡.md)，图片清单见 [12-图片资源逐项目录.md](12-图片资源逐项目录.md)，长期运营见 [13-官网运营与维护方案.md](13-官网运营与维护方案.md)。
>
> 网站仍在持续开发。此手册描述核对当日的本地工作区，不代表线上已发布版本。页面数量、图片数量及已有历史说明可能变化；以当前源码、构建结果和线上实际页面分别核对。

## 1. 先用 3 分钟认识网站

蓝辉轻改官网展示汽车轻改、膜类服务、车型适配、门店信息和品牌文章。访问者从首页进入产品中心，按品牌或服务查方案，再通过微信、电话或地址联系门店。

网站是“静态站”：内容写在电脑里的文字和图片文件中，运行构建命令后变成网页文件，最后由 Nginx 服务器提供访问。**这里没有可登录的后台编辑器，也没有“保存后线上立即变化”的功能。** 修改本地文件、验收本地网页、发布到线上是三件事；发布由有权限的负责人执行。

```text
业务资料/照片 → src/ 中的页面、数据或文章 + public/ 中的图片
             → 本地检查和构建 → out/ 静态网页 → 人工发布 → 线上网站
```

| 常见词 | 用白话说 | 例子 |
|---|---|---|
| 路由 | 网页的网址路径 | `/product/xiaomi/su7` |
| 页面 | 组成某个网址的入口文件 | `src/app/page.tsx` 是首页 |
| 组件 | 页面复用的外观或交互积木 | `src/components/Header.tsx` 是导航栏 |
| 数据文件 | 集中存放页面显示的内容 | `src/lib/store.ts` 存门店资料 |
| 静态构建 | 把源码变成可发布网页 | `npm run build` 生成 `out/` |
| 门禁 | 自动检查有没有常见错误 | `npm run check:static` |
| SEO | 搜索引擎看到的标题、网址和站点地图 | `src/app/sitemap.ts` |
| `slug` | 放在网址里的英文短名，改动会影响旧链接 | `su7`、`color-film` |
| `draft` | 博客草稿开关 | `draft: true` 不显示在已发布列表 |

## 2. 交接人每天先看什么

1. **接收修改请求**：写清页面网址、现有内容、想改成什么、图片原件、业务确认人、期望日期。不要只说“改一下产品”。
2. **确认内容是否可以公开**：门店电话/地址、技术参数、适配车型、产品声明、图片使用权都先找业务负责人确认。展示页不标价格，文案遵守 `rules/content-copy.md`。
3. **按任务查 [11-维护模块操作卡.md](11-维护模块操作卡.md)**：每张卡写了资料准备、源码位置、验收点和需要开发者的环节。
4. **改完查本地预览**：只看到了本地变化不等于线上已更新。把验收截图、页面网址和更改清单留存。
5. **发布由授权人处理**：交接人把资料、修改结果、检查结果交给发布负责人。仓库规则禁止代替人类执行 `git push` 和部署。

### 一个合格的修改需求（可直接复制）

```text
任务：更新蓝辉轻改顺德大良店营业时间
目标页面：https://lanhuiqinggai.com/contact 及门店详情页
当前内容：09:00-18:00
新内容：09:30-18:30（门店负责人已于 YYYY-MM-DD 确认）
需要检查：两个页面均显示新时间；电话和地址保持正确；手机端可见
素材与证据：负责人确认截图/文件路径
发布：由授权负责人安排，不把本地预览当成线上生效
```

## 3. 文件放在哪里

| 位置 | 内容 | 接手人通常做什么 |
|---|---|---|
| `src/app/` | 各个页面入口、全站布局、SEO 文件 | 根据页面网址定位入口；具体改动可交开发者 |
| `src/components/` | 导航、页脚、产品卡、车型区块、弹窗等 | 判断一处改动会影响哪些页面 |
| `src/lib/` | 品牌、门店、产品、适配、路由等数据 | 核对业务事实；结构或关联修改交开发者 |
| `src/content/articles/` | 博客 Markdown 原文 | 准备、校对和审核文章 |
| `public/images/` | 线上使用的本地图片 | 准备图片、核对授权、找到引用位置 |
| `scripts/` | 导入图片、生成数据、验收脚本 | 由开发者按任务执行；不随意双击或运行 |
| `e2e/`、`*.test.ts(x)` | 自动测试 | 修改后提供验收证据 |
| `rules/`、`adr/`、`specs/active/` | 当前规则、决策、任务规格 | 理解什么能改、为什么这样做；这些本地文档不进 Git |
| `官网材料导出/` | 对外说明、逐页说明和本手册 | 交接阅读材料；修改网站后按需更新快照 |
| `out/`、`.next/`、`node_modules/` | 构建结果、缓存、依赖 | 不手工修改或当作内容原稿 |
| `.env*`、`ops/deploy/` | 配置或历史部署脚本 | 不碰；需要时联系技术负责人 |

**查找口诀：** 找网址看 `src/app/`；找文字先查 `src/lib/` 和文章目录；找版式看 `src/components/`；找照片看 `public/images/`；找搜索收录看 `src/lib/product-routes.ts`、`src/app/sitemap.ts` 和页面元数据。详见逐文件索引。

## 4. 即使不会编程，也可以完成的工作

- 收集原始素材：车型、年款、配置、产品名称、参数来源、照片及授权、施工边界、门店信息。
- 在任务卡里标明每个字段的确认人和确认日期，避免从旧网页或历史报告复制未经核实的数字。
- 校对文章 Markdown 和页面文案；涉及极限词、保修、性能、适配的说法交业务负责人确认。
- 在本地预览中核对页面：标题、图片、链接、手机端、微信咨询、电话链接、门店地址。
- 记录问题：页面网址、复现步骤、期望与实际、截图、出现时间。

**需要开发者处理的事：** 新增页面或品牌、调整布局、修改适配算法/数据结构、批量导图、SEO 规则、报错修复、构建失败分析。接手人负责把业务事实与验收标准说清楚。

## 5. 本地预览和检查（有人带领时照着做）

前提：电脑已装 Node.js 24 或更高版本，仓库在本机。打开终端，进入项目根目录，再执行：

```bash
cd '/Users/fkycoya/Documents/交接文档/Lanhui-web-static'
npm ci
npm run dev -- --port 3100
```

浏览器打开 `http://localhost:3100`。终端不要关；结束预览时按 `Ctrl+C`。`npm ci` 通常仅在第一次安装或依赖变化后执行。若命令报错，把完整错误交开发者，不要猜测后删除文件。

开发者交付时至少提供：修改文件、预览网址、检查命令及退出码、关键页面截图。**正式发布前**由负责人执行 `npm run check:static` 并记录退出码，例如：

```bash
npm run check:static > /tmp/lanhui-check-static.log 2>&1; echo EXIT=$?
```

`EXIT=0` 才表示这条命令通过；仍须核对页面内容。不要使用 `| tail` 看退出码。构建结果在 `out/`，不要直接改它；下次构建会覆盖。

## 6. 发布、回退与资料保管

- 本手册不是发布授权。发布步骤以当前 `rules/deploy.md`、有效发布计划和负责人核准为准。历史 `ops/deploy/deploy.sh` 与旧部署说明可能失真，不照抄执行。
- 仓库的 `rules/`、`adr/`、`specs/`、`work/` 等本地文档被 `.gitignore` 忽略；交接时要单独备份。`官网材料导出/` 属于交付材料，可用 `bash 官网材料导出/_scripts/sync-all.sh /绝对路径/新的空目录` 生成一份独立快照。脚本不会覆盖非空目录。
- 发现线上问题先记录网址、时间、截图和影响范围，立即联系发布负责人；不要在服务器上直接改文件。
- `README.md`、`TODO.md` 和旧“官网材料导出”文档有历史快照，某些数量和部署描述已经过时。查当前状态以源码、最新门禁和线上核对为准。
