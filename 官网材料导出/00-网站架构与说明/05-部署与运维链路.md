# 部署与运维链路

> 核对：2026-10-24。本文件是交接说明，**不是部署指令或发布授权**。生产机器状态、备份路径和实际切换方式必须由授权发布人现场核实。最后可追溯的发布记录：`work/RELEASE-20261022.md`。

## 从改动到线上

```text
本地源码/图片/文章 → 业务审核 → 本地预览与静态门禁
                   → Next.js 构建 `out/` → 授权人发布
                   → 公网 HTML、图片、链接与联系入口复核
```

本项目 `next.config.ts` 为 `output: "export"`，生产由 Nginx 提供静态文件。改动本地文件不会自动更新线上；`npm run build` 只生成本地 `out/`。`ops/deploy/` 下脚本与生产路径不一致，是历史模板，不执行。

## 发布前交接包

| 需要交给发布人 | 最低要求 |
|---|---|
| 变更清单 | 修改文件、受影响网址、业务确认人、图片授权与来源 |
| 验收证据 | 桌面/手机预览、关键事实核对、静态门禁日志和退出码 |
| 产物核对 | `out/` 生成成功；图片与 HTML 可公开读取；sitemap 和 canonical 用裸域 |
| 回退准备 | 明确上一版可用产物、备份位置、回退责任人；先核实生产现状 |

```bash
find out -type f ! -perm -o=r | wc -l
```

第一条应得到 `EXIT=0`；第二条应为 `0`。历史上源图片权限导致线上 403，不能只看 HTML 是否能访问。不要用管道取得构建命令退出码。构建要串行，服务器为 2C2G 小机；详见 `rules/deploy.md` 与 `adr/0002-single-build-on-2c2g.md`。

## 日常维护与故障处理

- 每次发布前由授权人核对生产现状、备份和发布目标；成功后抽查首页、联系页、重点产品/车型页、文章、图片、`robots.txt`、`sitemap.xml`。
- 出现 403：先查图片/文件可读权限；出现 404：查页面是否导出、链接与路由是否一致；出现旧内容：查构建与发布版本、缓存和 URL；联系入口失效：先记录页面、设备、时间并通知门店。
- 故障记录保留：时间、网址、截图、影响范围、最后正常版本、处理人、修复/回退结果。不要直接在服务器文件里手改文案。
- 线上恢复和回退由授权发布人操作；完成后重新核对公网关键路径。
