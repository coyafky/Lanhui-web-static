# 蓝辉轻改官网运营与维护方案

> 版本：2026-10-24。适用：顺德大良店当前纯静态官网。依据当前本地源码、`AGENTS.md`、`rules/` 和 `specs/active/commercial-website-readiness-roadmap.md` 整理。本文是工作方法，不代表线上已部署本地改动，也不授权推送或部署。

## 1. 运营目标与现实边界

官网的首要任务是让访客找到适合自己的服务/车型说明，理解适配与施工边界，并能联系门店。它没有后台、客户数据库、在线报价或订单系统。电话/微信按钮点击只能表示尝试联系，**有效咨询**要由门店确认。产品展示页不标价格，最终方案由门店核车后确认。

建议先把以下四件事做稳：

1. **事实准确**：门店电话、地址、营业时间、适配车型、产品参数和施工声明有来源和复核人。
2. **联系畅通**：手机端可找到电话/微信/到店入口，门店有人接待并记录结果。
3. **内容有用**：优先维护已有高意图服务和车型页，给出可验证的场景、限制、图片和常见问题。
4. **发布可控**：每次修改有业务审核、本地验收、静态门禁、线上复核和回退联系人。

## 2. 责任分工

| 角色 | 要负责的结果 | 交付给下一环节 |
|---|---|---|
| 经营/门店负责人 | 服务范围、营业信息、适配与参数、接待承诺属实 | 已确认的事实、确认日期、原始资料、变更优先级 |
| 内容运营 | 需求卡、文章/页面草稿、关键词与用户问题、图片授权台账 | 文案、目标网址、配图、证据、验收标准 |
| 开发维护人 | 代码与数据一致、页面可用、构建通过 | 变更清单、本地预览、门禁退出码、受影响页面 |
| 验收人 | 业务事实、手机端体验、联系入口和图片核对 | PASS/FAIL 记录、截图、待修项 |
| 授权发布人 | 备份、发布、线上复核、异常回退 | 发布时间、发布版本、线上抽查与回退记录 |

一人可兼任多个角色，但每项变更要写明“事实谁确认、谁验收、谁发布”。不在聊天记录里只留一句“已改好”。

## 3. 固定节奏

| 频率 | 运营动作 | 最小记录 |
|---|---|---|
| 每日营业时 | 核对电话/微信可接通；看是否有客户反馈的错图、错链、过期信息 | 异常网址、时间、设备、截图、处理人 |
| 每周 | 汇总咨询问题与未找到答案的页面；核对重点页面 3–5 个手机端入口；选择下一周内容/修正项 | 页面、用户问题、优先级、负责人 |
| 每月 | 复核门店 NAP（名称/地址/电话）与营业时间；抽查服务/车型参数；看搜索平台的页面和查询表现；核对图片授权与失效链接 | 来源数据区间、变化原因、待办与完成证据 |
| 每季度 | 复核重点服务与车型目录、旧页面/重复内容、静态门禁和回退演练记录；整理过期文档 | 保留/更新/下线清单与业务确认 |
| 每次发布 | 走第 5 节的变更闭环 | 版本、门禁、线上抽查、回退位置 |

若运营人手有限，先保证每日联系入口、每月事实复核和每次发布验收；内容量再按可审核能力安排。

## 4. 内容与获客优先级

先从门店真实咨询提炼内容，再决定新页面。每个候选主题至少写出：用户问题、对应服务/车型、业务资料来源、目标网址、希望客户采取的下一步。优先顺序建议：

1. **P0 正确性**：错误电话/地址/时间、错误适配、失效图片/链接、误导性承诺。发现即修。
2. **P1 高意图现有页**：已有服务和车型页补齐年款/配置边界、实拍图、施工说明、常见问题与联系入口。
3. **P2 新内容**：在有真实素材、明确受众和审核人时写文章或新车型页；避免为扩充路由数量而生产空壳页。

文章建议围绕门店反复遇到的实际问题：适配差异、选材与施工流程、保养与质保边界、到店准备、已获授权的案例。每篇要有负责人核实的事实与图片；标题和正文遵守 `rules/content-copy.md`。已有 23 篇已发布文章是源码数量，不表示仍全部准确，应分批复核。

## 5. 一次变更的闭环

1. **登记需求**：目标 URL、旧/新内容、原因、素材路径、事实来源、确认人、期望生效时间。
2. **检查影响**：找页面 import 和数据源；若改品牌/门店事实，同时查页头页脚、联系页、门店页、schema；若改路径，查导航、sitemap、llms.txt 与旧链接。
3. **内容审核**：参数与适配由业务核对；图片有使用权；页面不标价格；文案禁极限词且标清实际核验边界。
4. **本地实现与验收**：在 3100 端口查目标页与关联页的桌面/手机、图片、链接、电话/微信；记录截图。发布前运行 `npm run check:static > /tmp/lanhui-check-static.log 2>&1; echo EXIT=$?`。
5. **交付发布人**：附修改文件、受影响 URL、审核记录、门禁退出码、页面截图、待确认项；发布人核对当前生产和备份后执行发布。
6. **线上复核**：记录版本、时间、目标页、关键图片、联系入口、sitemap/robots 的结果；有问题先控制影响，再修复或回退。

源码、构建产物、线上网站是三个不同状态。当前本地有未提交改动，不能用本地页面截图证明线上已经变化。

## 6. 运营台账：只保留能用于决策的指标

前四周先建立基线，不预设增长百分比。按周记录：

| 指标 | 定义 | 来源/限制 |
|---|---|---|
| 有效咨询数 | 门店确认已发生双向沟通，且有明确车型或服务需求 | 门店人工台账；页面点击不计入 |
| 来源可识别率 | 有效咨询中能确认入口/渠道的比例 | 门店询问与记录；未知保持“未知”，不猜测 |
| 响应时长 | 从客户首次联系到门店首次有效回复 | 门店消息/电话记录；先观察分布再设目标 |
| 到店/预约数 | 已确认预约或到店的有效咨询 | 门店记录，避免与“点击导航”混淆 |
| 搜索可见度 | 搜索平台的查询、展示、点击和被收录页面 | 以平台实际数据为准；没有接入就标“未接入” |
| 内容质量问题 | 参数错误、失效链接、错图、页面不可读等 | 问题台账，按严重程度和修复时间复盘 |

台账记录必要的业务信息即可，访问权限、保存位置和保留期由负责人指定。公开文档和普通分析事件中不放客户姓名、电话或聊天内容。若没有分析平台，先用门店台账与可用的搜索平台数据；不要把“没有数据”写成 0。

## 7. 事件处理和升级

| 现象 | 先做什么 | 谁处理 |
|---|---|---|
| 电话/微信入口失效 | 记录页面、设备、时间；门店提供临时可联系渠道 | 门店负责人 + 开发维护人 |
| 适配/参数错误 | 暂停将该页用于推广，核对原始资料和受影响车型 | 业务负责人 + 内容运营 |
| 图片 403/404 | 查目标图片 URL、`public/images/` 引用、导出文件权限 | 开发维护人 + 发布人 |
| 页面 404/旧内容 | 查当前发布版本、静态导出、路由、缓存和裸域跳转 | 开发维护人 + 发布人 |
| 构建或门禁失败 | 保留完整日志和退出码，不发布这次改动 | 开发维护人 |
| 线上大面积不可用 | 保留证据，通知授权发布人按已确认备份恢复 | 发布人 |

技术处理完成后，门店再次确认业务信息；线上复核应覆盖原故障路径和邻近页面。

## 8. 何时再考虑工具升级

当前流程可以用人工台账和源码维护。连续观察至少一个运营周期后，再根据真实瓶颈讨论：需要多人非技术编辑时评估内容管理系统；需要可靠记录咨询时评估企业微信/现有 CRM 或托管表单；需要转化分析时先定义事件与隐私边界。任何新系统都要有内容/数据权威源、负责人、备份与发布机制，不能让运营数据散在几套工具里。
