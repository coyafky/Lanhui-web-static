# SEO 与 GEO 现状及维护

> 核对：2026-10-24，本地源码快照。这里只描述已实现的文件和维护方法，不把搜索收录、排名或 AI 引用当作已验证成效。线上表现须以站长平台、流量来源和实际咨询记录核实。

## 已实现的基础

| 事项 | 源码与当前规则 | 维护动作 |
|---|---|---|
| 正式域名 | `src/lib/site-url.ts`：生产默认 `https://lanhuiqinggai.com`；`next.config.ts` 开尾斜杠 | 新页面检查 canonical、内链和裸域一致性；`www` 跳转需线上核实 |
| sitemap | `src/app/sitemap.ts` 从静态入口、路由注册表、窗膜套餐、轮毂、门店和文章生成 | 本地当前调用得到 577 条；发布后以公网 sitemap 核对数量、地址和实际页面 |
| robots | `src/app/robots.ts` 放行公共页面，列出 sitemap；对部分 AI 爬虫显式放行 | 新增私有能力前复核规则；不要把放行等同于已收录 |
| llms.txt | `src/app/llms.txt/route.ts` 从品牌、门店、live 服务、全部车型和文章生成官方入口 | 增减内容后检查链接、事实和语言；AI 是否引用需独立观测 |
| 页面元数据 | 页面 `metadata`、结构化数据、`src/lib/json-ld.ts` | 改标题、说明、地址、服务范围时同步看页面源码与生成 HTML |

`ALL_MODELS` 中问界 M6/M7/M8 虽标记 `planned`，但 sitemap 和 llms.txt 当前仍会纳入，原因是代码直接枚举全部车型。内容负责人应核对这些页面是否满足公开质量要求，不能只凭状态名判断收录范围。`business-comfort` 为服务占位页，sitemap 只收录 `live` 服务，不纳入它。

## 每月复核一张表

| 检查 | 证据 | 处理规则 |
|---|---|---|
| 重点页面是否可抓取、可访问 | 公网 URL、状态码、页面 HTML、站长平台覆盖报告 | 将 404、空白、重复 canonical 记为待修问题 |
| 搜索表现 | 搜索查询、点击、展示、重点页面变化 | 区分品牌词、服务词、车型词；只记录可核实数据 |
| 内容质量 | 页面事实来源、更新时间、图片和内链 | 先修不准确的参数与适配信息，再扩写内容 |
| 咨询质量 | 门店人工记录的来源、主题、后续结果 | 按页面/渠道复盘；按钮点击不等于有效咨询 |
| AI 可见度 | 固定问题清单、引用网址与日期 | 记录是否引用官网及是否正确，不承诺搜索结果 |

新增或更新页面时：核对 `product-routes.ts` → 页面 metadata → sitemap/llms.txt → 内链 → 本地构建 → 线上页面。站点地图中的 `lastModified` 对多数路由取构建时间，不等于内容最后修改时间；运营分析不要把它当编辑记录。具体节奏见 [13-官网运营与维护方案.md](13-官网运营与维护方案.md)。
