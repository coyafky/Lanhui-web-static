# 技术栈与工程结构

> 核对：2026-10-24，本地源码快照。版本以 `package.json`、行为以代码和构建结果为准。

## 技术边界

| 层 | 当前实现 | 维护含义 |
|---|---|---|
| 框架 | Next.js 16.2.1 App Router、React 19.2.4 | 改页面前先读本项目 `node_modules/next/dist/docs/` 对应指南 |
| 输出 | `next.config.ts`：`output: "export"`、`trailingSlash: true`、图片不走服务端优化 | `npm run build` 生成 `out/`；没有运行时 Node 服务 |
| 语言与样式 | TypeScript 5、Tailwind CSS 4 | 内容模块、组件和页面共同组成静态网页 |
| 文章 | `src/content/articles/*.md`，由 `src/lib/blog.ts` 构建时读取 | 草稿不会进入已发布列表；改完必须重建 |
| 图片 | `public/images/` | 路径和文件名与代码引用一致；静态图片检查必须通过 |
| 检查 | ESLint、TypeScript、Vitest、静态资源/边界/产物校验 | 发布前运行 `npm run check:static` |
| 运行环境 | `package.json` 要求 Node >=24 | 本地/构建机版本要满足要求 |

## 找文件

| 想改什么 | 权威入口 |
|---|---|
| 页面网址与布局 | `src/app/`；共享展示在 `src/components/` |
| 品牌、车型、服务路径 | `src/lib/product-routes.ts` |
| 具体服务/车型内容 | `src/lib/*-products.ts`、`*-page-config.ts`、对应页面或组件；先查页面 import |
| 品牌与门店事实 | `src/lib/brand.ts`、`src/lib/store.ts`、`src/lib/store-query.ts` |
| 博客 | `src/content/articles/`、`src/lib/blog.ts` |
| SEO | `src/app/sitemap.ts`、`robots.ts`、`llms.txt/route.ts`、`src/lib/site-url.ts`、各页 metadata |
| 线上图片 | `public/images/`；查引用后再替换 |
| 规则与任务 | `AGENTS.md`、`rules/`、`adr/`、`specs/active/`、`work/COLLAB.md` |

`src/lib/wheels.data.ts` 是生成物，禁止手改；`out/` 与 `.next/` 也是构建产物。`ops/deploy/` 是历史模板，不当作生产部署命令。`specs/`、`adr/`、`rules/`、`work/` 是本地忽略目录，交接时需要单独备份。

## 常用命令

```bash
npm ci                         # 首次安装或依赖变化后
npm run dev -- --port 3100     # 本项目本地预览
npm run lint                   # 代码规范
npm run typecheck              # 类型
npm test                       # 单元/组件测试
npm run check:static > /tmp/lanhui-check-static.log 2>&1; echo EXIT=$?
```

`check:static` 依次运行 lint、typecheck、test、图片与轮毂校验、静态边界检查、build、静态产物检查。发布前还要核对页面中的业务事实、图片、链接和移动端交互。命令退出码为 0 只代表该项检查通过。
