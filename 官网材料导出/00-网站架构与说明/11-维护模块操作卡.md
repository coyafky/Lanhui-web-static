# 蓝辉轻改官网｜维护模块操作卡

> 读者：网站交接人及协作开发者。核对日期：2026-10-24。先读 [09-零基础交接操作手册.md](09-零基础交接操作手册.md)。本页把“我要改什么”对应到“找谁确认、看哪个文件、怎么验收”。页面数据由本地源码构建，保存文件不会直接更新线上。

## 通用流程（所有任务都走一遍）

1. **登记**：记录目标网址、修改前后、素材来源、业务确认人、截止日期。
2. **查规则**：文案看 `rules/content-copy.md`；样式看 `DESIGN.md` 和 `rules/ui.md`；新网址与 SEO 看 `rules/seo.md`。
3. **定位**：用下方操作卡和 [10-网站文件逐项批注.md](10-网站文件逐项批注.md) 找源文件。页面名相同不代表只改一个文件。
4. **修改与复核**：开发者负责源码修改；交接人对照原始资料逐项核字、核图、核链接。
5. **本地验收**：在 3100 端口预览目标页和手机屏幕；发布前由负责人跑 `npm run check:static` 并记录 `EXIT`。
6. **交付**：列出改动文件、受影响网址、截图、检查结果、待确认项。线上发布与回退由授权负责人操作。

## 模块 1｜品牌名称、电话、地址、营业时间

| 项目 | 操作 |
|---|---|
| 先准备 | 新信息原文、门店/品牌负责人确认、何时生效 |
| 主要来源 | `src/lib/brand.ts` 存全站品牌资料；`src/lib/store.ts` 存公开门店记录 |
| 会出现的地方 | 首页、导航/页脚、`/contact`、`/agent`、门店详情、SEO 结构化数据 |
| 需开发者检查 | `src/app/contact/page.tsx` 中可能有独立写入的文案；`src/components/Header.tsx`、`Footer.tsx` 等是否引用同一数据 |
| 验收 | 电话点击可拨号；地址与导航地图一致；营业时间在联系页和门店页一致；手机端可读 |

门店只放**真实且获准公开**的信息。地图经纬度须确认坐标系；`src/lib/store.ts` 使用 GCJ-02。`isActive: false` 会使门店不出现在公开查询中，省市页面也可能随之改变，不能仅把它当作“隐藏一张卡片”。

## 模块 2｜博客文章与案例

| 项目 | 操作 |
|---|---|
| 先准备 | 标题、摘要、分类、发布日期、正文、封面图、事实来源、图片授权 |
| 主要来源 | `src/content/articles/*.md`；解析及草稿逻辑在 `src/lib/blog.ts` |
| 页面入口 | `src/app/blog/page.tsx`、`src/app/blog/[slug]/page.tsx`、分类/分页页 |
| 简单字段 | `title` 标题；`slug` 网址短名；`description` 搜索摘要；`category` 分类；`publishedAt` 日期；`featuredImage` 封面；`draft` 草稿 |
| 验收 | 列表有文章；分类正确；正文标题/段落/链接正确；封面存在；文章网址与 `slug` 一致；sitemap 收录已发布文章 |

文章开头示例：

```md
---
title: 文章标题
slug: example-article
description: 给搜索结果看的简短摘要
category: 门店服务
publishedAt: 2026-10-24
featuredImage: /images/example.webp
draft: true
---

正文第一段。
```

**先用 `draft: true` 审稿**；业务批准后由开发者改成 `false`、构建并验收。当前解析器只支持每行一个 `key: value` 的简单头部字段；不要自行写复杂 YAML。已有文章的 `slug` 改动会影响旧链接，须按网址变更任务处理。不得把未经核实的案例、参数或承诺当作事实发布。

## 模块 3｜产品中心、品牌与车型

| 项目 | 操作 |
|---|---|
| 先准备 | 品牌/车型标准名称、年款配置、升级项目、适配依据、不可适配边界、图片、审核人 |
| 主要来源 | `src/lib/product-routes.ts` 管 `/product` 路由及导航；各 `*-products.ts`、`*-curated-models.ts`、`*-curated-projects.ts`、`src/lib/fitment/` 管内容与适配 |
| 页面入口 | `src/app/product/**/page.tsx`；复用渲染器在 `src/components/vehicle-page/`、`src/components/brand-series/` |
| 特别注意 | 一个品牌的导航、品牌页、车型页、图片、SEO 和 sitemap 可能牵涉多个文件；交开发者整体处理 |
| 验收 | 产品中心能找到品牌；品牌页能找到车型；项目、参数、图片和免责声明一致；不可用路径不意外出现 |

`status: "live"` 与 `"planned"` 由注册表控制，但不能凭它判断“页面已经全部可用”：仍须打开页面实际核对。所有技术适配以具体车辆和门店实测为准。**产品展示页不标价格。**

## 模块 4｜膜类、轮毂、底盘等服务页

| 模块 | 内容入口 | 页面/组件入口 | 重点验收 |
|---|---|---|---|
| 隐形车衣 PPF | `src/lib/film-products.ts`、`src/lib/products.ts` | `src/app/product/ppf/page.tsx`、`src/components/film/` | 系列名称、参数、免责声明 |
| 汽车窗膜 | `src/lib/window-film-details.ts`、`src/lib/products.ts` | `src/app/product/window-film/`、`src/components/window-film/` | 套餐名、参数对应、详情页与列表一致 |
| 改色膜 | `src/lib/film-products.ts`、`src/lib/products.ts` | `src/app/product/color-film/page.tsx`、`src/components/color-film/` | 颜色/案例图、施工文案 |
| 轮毂 | `src/lib/wheel-catalog.ts`、`src/lib/wheel-catalog-projection.ts` | `src/app/product/wheels/`、`src/components/product/wheel/` | 型号、图片、详情页、适配/合规边界 |
| 电动踏板与底盘 | 对应 `src/lib/*products.ts`、`*fitment.ts` | `src/app/product/electric-steps/`、`chassis/` | 适配年款与安装边界 |
| 脚垫/地板/座舱 | `src/lib/carmat-products.ts`、`flooring-products.ts` 等 | 对应 `src/app/product/` 页面 | 材质、结构图、车型适配 |

轮毂数据 `src/lib/wheels.data.ts` 是脚本生成物，**不手改**。要改轮毂源资料，交开发者检查 `scripts/build-wheel-data.mjs` 及数据来源，再执行 `npm run wheels:data` 和 `npm run wheels:verify`。套餐、规格字段互相关联，不建议零基础交接人直接修改 TypeScript。

## 模块 5｜图片与二维码

| 项目 | 操作 |
|---|---|
| 先准备 | 原图、拍摄/使用授权、车型及项目对应关系、替代文字、图片比例 |
| 资源位置 | `public/images/`；详细逐项清单见 [12-图片资源逐项目录.md](12-图片资源逐项目录.md) |
| 引用方式 | 源码使用 `/images/...` 形式；例如 `/images/stores/image.webp` 对应 `public/images/stores/image.webp` |
| 开发工作 | 检查文件大小/格式、更新引用、必要时跑图片导入或验证脚本 |
| 验收 | 桌面和手机均加载正确图；图与车型/配置对应；放大不糊；旧图没有误留；二维码可正常识别 |

图片文件名不能随便改：页面数据常用固定路径引用。不要把评审截图或历史报告图片放进 `public/images/`。新图可能涉及授权、压缩、裁切和标注，资料不齐时先留待确认，不拿相似车型图片冒充。

## 模块 6｜导航、链接、SEO 和新页面

| 项目 | 操作 |
|---|---|
| 先准备 | 页面标题、正式网址、旧网址是否要保留、摘要、上级栏目、是否收录 |
| 主要来源 | `src/lib/product-routes.ts`；`src/components/Header.tsx`；各页 `metadata`；`src/app/sitemap.ts`；`src/app/robots.ts`；`src/lib/site-url.ts` |
| 验收 | 导航可到达；旧链接按要求处理；标题/摘要正确；canonical 使用正式裸域；sitemap 与实际页面对应；页面不存在时返回正确状态 |

网址是对外资产，改 `slug` 会影响二维码、搜索结果、社媒链接。请开发者检查旧路径和新路径的映射。本站正式域名为 `https://lanhuiqinggai.com`；不要从旧资料复制 `www` 口径或历史页面数量。

## 模块 7｜咨询入口和门店地图

| 项目 | 操作 |
|---|---|
| 先准备 | 新电话、微信二维码、地图坐标及实测导航位置 |
| 主要来源 | `src/lib/brand.ts`、`src/lib/store.ts`、`src/lib/store-map.ts`、`src/components/WeChatConsultButton.tsx`、`src/components/shared/WeChatConsultModal.tsx` |
| 页面 | `/contact`、`/agent`、门店详情、全站导航与页脚 |
| 验收 | 微信弹窗能打开并关闭；手机拨号链接正确；高德导航落点正确；二维码实际扫码测试 |

不要只对照图片上印的号码：源码里可能还有电话链接 `tel:`、品牌资料和门店资料需要同步。

## 模块 8｜样式、手机端和交互

| 项目 | 操作 |
|---|---|
| 主要来源 | `src/app/globals.css`、`DESIGN.md`、`src/components/`、`src/app/**/page.tsx` |
| 需要开发者 | 页面布局、颜色、字体、吸顶导航、选项卡、弹窗、响应式样式 |
| 交接人验收 | 电脑和手机各看一遍；导航、Tab、按钮可点；文字不遮挡；图片比例正常；没有明显横向滚动 |

视觉改动可能影响全站共用组件。让开发者说明受影响页面，不只检查提出需求的那一页。

## 模块 9｜质量检查、线上异常和发布

| 场景 | 操作 |
|---|---|
| 小修后 | 开发者按改动运行 lint、typecheck、测试或构建；交接人核对页面事实 |
| 发布前 | 授权负责人运行 `npm run check:static`，记录 `EXIT=0` 与关键结果；按发布计划人工复核 |
| 页面打不开 | 记录完整 URL、时间、设备、截图；区分线上/本地；交开发者定位 |
| 图片缺失 | 记录图片所在页和位置；查 `public/images/` 及引用路径；交开发者跑资源检查 |
| 线上内容不对 | 先核对线上是否已发布该版本；提供预期内容、来源和截图；不要直接改 `out/` 或服务器文件 |

质量命令在 `package.json`。`npm run check` 与 `npm run check:static` 不同，后者才是完整静态发布门禁。仓库长期存在大量未提交文件，交接时应记录 `git status --porcelain`；不要为了“清空状态”随意删除或提交它们。
