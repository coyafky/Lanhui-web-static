# 内容数据模型

> 网站的「内容」全部是 TypeScript 数据对象或 Markdown 文件。本文件如实抄录核心类型并加中文字段说明，作为「新增/修改内容」的操作参考。
> 📌 **命名澄清**：任务书提到的 `BrandRoute` / `ServiceCategoryRoute` / `StoreArticle`，本仓库实际类型名是 **`VehicleBrandRoute` / `ServiceRoute` / `Article` + `Store`**（无 `StoreArticle`），下文以源码为准。

## 一、路由注册表模型（`src/lib/product-routes.ts`，全站路由 source of truth）

```ts
export type ProductRouteType = "service_category" | "vehicle_brand" | "vehicle_model";
export type ProductRouteStatus = "live" | "planned";     // live=已上线 / planned=规划中
export type ProductRoutePriority = "P0" | "P1" | "P2";   // 驱动 sitemap priority
export type ServiceGroup = "film" | "light_mod" | "business_comfort" | "practical_accessory" | "car_care";
export type AccentColor = "cyan"|"orange"|"amber"|"emerald"|"violet"|"pink"|"blue"|"teal"|"red"|"sky";

export type ProductRoute = {
  type: ProductRouteType;            // 路由类型
  canonicalPath: string;             // 正式 URL（唯一）
  legacyPaths?: readonly string[];   // 旧 URL（301 归一）
  title: string;                     // 页面 SEO 标题
  navLabel: string;                  // 导航显示名
  status: ProductRouteStatus;
  priority: ProductRoutePriority;
};

export type VehicleBrandRoute = ProductRoute & {   // 品牌系列页（L1）
  type: "vehicle_brand";
  brandSlug: string;                 // 品牌 URL 段，如 "xiaomi"
  brandName: string;                 // 品牌中文名，如 "小米"
  accentColor: AccentColor;
  modelSlugs: readonly string[];     // 该品牌下的车型 URL 段
};

export type VehicleModelRoute = ProductRoute & {   // 车型详情页（L2）
  type: "vehicle_model";
  brandSlug: string;
  modelSlug: string;                 // 车型 URL 段，如 "su7"
  modelName: string;                 // 显示名，如 "小米 SU7"
  parentPath: string;                // 上级品牌页，如 "/product/xiaomi"
  projectCount?: number;             // 注册表登记项目数（⚠ 可能与页面实际数不一致）
  sourcePrd: string;                 // 对应 PRD 路径
};

export type ServiceRoute = ProductRoute & {        // 服务/分类页
  type: "service_category";
  serviceSlug: string;
  group: ServiceGroup;               // 业务分组
};
```

| 导出 | 含义 |
|---|---|
| `ALL_BRANDS` / `ALL_MODELS` / `ALL_SERVICES` | 12 品牌 / 19 车型 / 12 服务 |
| `ALL_LEGACY_ALIASES` | 旧→新路径映射（由各车型 `legacyPaths` 展开） |
| `getBrandRoute / getModelRoute / getServiceRoute` | 按 slug 查询 |
| `getCanonicalFor(path)` | 旧路径 → 正式路径 |
| `getModelsByBrand(brandSlug)` | 品牌下的车型 |
| `getLiveBrands() / getLiveServices()` | 只取 `status === "live"` |

## 八、博客文章模型（`src/lib/blog.ts`，内容为 Markdown 文件）

```ts
export type ArticleMeta = {
  slug: string;              // URL 段（缺省取文件名）
  title: string;             // 必填，标题
  description: string;       // 摘要（缺省从正文自动截取）
  category: string;          // 分类中文名（缺省 "品牌资讯"）
  publishedAt: string;       // 必填，格式 YYYY-MM-DD
  featuredImage?: string;    // 封面图（站点内路径）
  draft: boolean;            // true 则不发布
};

export type Article = ArticleMeta & {
  content: string;           // Markdown 正文
  readingMinutes: number;    // 估算阅读时长（中文约 400 字/分钟）
};
```

分类中文名 → URL slug（`CATEGORY_SLUGS`）：`改色膜→cat-paint-film`、`窗膜→cat-window-film`、`轮毂→cat-wheel`、`门店服务→cat-store-service`、`车主案例→cat-case`。

## 九、操作手册：新增内容要改哪几处

### 9.1 新增一个车型页（共 5 步）

| 步骤 | 改哪里 | 具体动作 |
|---|---|---|
| **1. 注册路由** | `src/lib/product-routes.ts` | 在 `MODELS` 加一条 `VehicleModelRoute`（brandSlug/modelSlug/modelName/parentPath/canonicalPath/title/navLabel/status/priority/projectCount/sourcePrd，有旧链接加 `legacyPaths`）；若属新品牌，另在 `BRANDS` 加品牌并把 modelSlug 填进 `modelSlugs` |
| **2. 准备数据** | `src/lib/<brand>-products.ts` 或 `<brand>-upgrade-projects.ts` | 新增/复用项目清单、场景、FAQ、Hero 图（含 `ImageStatus` 标注） |
| **3. 页面配置** | `src/lib/<brand>-<model>-page-config.ts` | 新建配置，映射为 `VehiclePageConfig`（至少 theme/hero/projects/scenarios/serviceFlow/faq） |
| **4. 创建页面** | `src/app/product/<brand>/<model>/page.tsx` | 写 `metadata`（title/description/canonical/OG），用 `getBrandRoute`/`getModelRoute` 校验，渲染 `<VehiclePageRenderer>`，注入 `ItemList` JSON-LD 与面包屑 schema |
| **5. 自检 + 构建** | 全仓 | 跑 `npm run check`；导航（Header）、`sitemap.ts`、`llms.txt` 均从 `ALL_BRANDS`/`ALL_MODELS` 自动派生，**无需手工改**；最后补一份 `04-车型详情页/<车型>.md` |

> 💡 口径一致：`projectCount` 必须与页面实际渲染项目数、Hero「N 项」一致（现有多个车型不一致，见 `08-已知问题与改进路线.md`）。

**新增产品大类页 / 博客：**

| 内容 | 步骤 |
|---|---|
| **产品大类页** | ① `product-routes.ts` 的 `SERVICES` 加 `ServiceRoute` → ② `products.ts` 的 `products` 加产品对象（或新建品类数据文件）→ ③ 新建 `src/app/product/<serviceSlug>/page.tsx` → ④ 跑门禁构建（sitemap/llms.txt/导航自动更新） |
| **博客文章** | ① `src/content/articles/` 新建 `<slug>.md` → ② frontmatter 必填 `title`、`publishedAt`（YYYY-MM-DD），建议填 `description`/`category`/`featuredImage` → ③ 新分类在 `blog.ts` 的 `CATEGORY_SLUGS` 登记 → ④ 跑构建（自动进列表/分页/分类页/sitemap） |

**一句话总结**：内容层是「**注册表（product-routes）+ 数据文件（*-products / *-page-config）+ Markdown（articles）**」三层结构；新增内容的本质 = **在对应源文件加数据 → 建页面 → 跑门禁构建**，导航与 sitemap 自动跟随。
