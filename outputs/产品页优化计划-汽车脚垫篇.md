## 一、优化逻辑说明

**汽车脚垫 = 底盘护板/电动踏板同一逻辑**（车型覆盖导向），但与那两个又有一处关键差异：

| 维度 | 轮毂页 | 底盘护板 / 电动踏板页 | **汽车脚垫页** |
|---|---|---|---|
| 客户决策路径 | "我有什么款式" | "我的车能不能装" | **"我的车支持哪几种脚垫"** |
| 核心卖点 | 工艺/尺寸/参数 | 品牌覆盖广 + 车型多 | **车型多 + 一个车型可配多种产品** |
| 页面重心 | 产品图库+参数筛选 | 品牌墙 + 车型搜索 | **车型搜索 + 产品类型矩阵** |
| 数据结构 | 产品 → 参数 | 车型 → 方案 | **车型 → 产品类型 × 规格** |

### 核心展示原则（用户明确要求）

> **展示"这个车型支持这个产品"，而不是"按供应商区分不同方案"**

✅ 正确：`比亚迪 汉EV` → 支持 `360脚垫`（3片/4门5座/16款起）+ `平面尾箱`
❌ 错误：`比亚迪 汉EV` → 方案1（供应商A）+ 方案2（供应商B）

**好消息**：脚垫数据里**根本没有供应商字段**，天然符合这个要求，无需脱敏。

## 五、数据导入策略

### 5.1 数据源

| 数据 | 位置 | 格式 | 数量 |
|---|---|---|---|
| 品牌数据 | `json/brands/` | JSON | 134 |
| 车型数据 | `json/models/` | JSON | 3492 |
| 产品类型数据 | `json/products/` | JSON | 3 |
| 产品实拍图 | `image/` | webp | 29 |

### 5.2 数据转换

```
json/brands/*.json (134) + json/models/*.json (3492) + json/products/*.json (3)
→ 解析聚合
→ src/lib/carmat-fitment.ts（品牌 + 车型 + 产品类型矩阵 + 搜索索引）
```

**关键处理**：
1. 品牌名从 `car_brand` 提取
2. 车型名从 `car_model` 提取
3. **产品类型从 `records` 的 keys 提取** ← 核心（决定"这个车型支持什么"）
4. 每条记录提取：适用年份 / 产地 / 门座信息 / 片套信息 / 数据状态
5. **过滤内部字段**：记录ID / 来源工作表 / 来源行 / 打版责任人 / 打版时间 / 附加数据 / 续行数据
6. `待补编号` 状态 → 前端标注"到店确认"
7. 搜索索引：品牌名 + 车型名 → 全文搜索

### 5.3 汽车脚垫 vs 底盘护板的数据差异

| 维度 | 底盘护板 | 汽车脚垫 |
|---|---|---|
| 有供应商字段 | ✅ 有（需过滤） | ❌ **无**（天然干净） |
| 方案结构 | 方案1/方案2（按供应商） | **产品类型平铺**（360脚垫/平面尾箱） |
| 需过滤字段 | supplier / supplier_coverage | 打版责任人 / 打版时间 / 记录ID |
| 核心展示 | 车型 → 方案 | **车型 → 产品类型矩阵** |
