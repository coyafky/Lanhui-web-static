## 一、优化逻辑说明

**包围 = 车型覆盖导向的简化版**

| 维度 | 底盘护板 | 汽车脚垫 | **包围** |
|---|---|---|---|
| 汽车品牌数 | 121 | 134 | **10** |
| 车型数 | 1534 | 3492 | **30** |
| 优化格式 | 品牌墙 + 车型搜索 | 品牌墙 + 车型搜索 | **品牌 + List（简化）** |
| 理由 | 品牌多，需要筛选器 | 品牌多，需要筛选器 | **品牌少，直接平铺即可** |

**包围的购买逻辑**：
1. 客户先确认"我的车型有没有包围套件"
2. 客户再看"有哪些部件"（前唇/后唇/侧裙/整套/尾翼）
3. 客户关心材质/工艺/颜色（ABS 吸塑、亮黑/哑黑）

因为**只有 10 个汽车品牌 / 30 个车型**，不需要复杂的搜索+筛选，直接「品牌 → 车型 List → 部件」三级平铺即可。

## 四、优化方案

### 4.1 页面结构（品牌 + List）

**要点**：
- 默认展开车型最多的品牌（理想），其余折叠 → 首屏信息密度高

- 缩略图 2-4 张，点击展开产品明细

### 4.3 数据模型

```typescript
export type BodyKitPart =
  | "前唇" | "后唇" | "侧裙" | "整套" | "尾翼"
  | "前包围" | "后包围" | "侧面";  // 两套命名需归一

export interface BodyKitBrand {
  name: string;                // "理想"
  modelCount: number;          // 12
  parts: BodyKitPart[];        // 该品牌覆盖的部件（去重）
  models: BodyKitModelSummary[];
}

export interface BodyKitModelSummary {
  brand: string;               // "理想"
  model: string;               // "理想L9"
  parts: BodyKitPart[];        // ["前包围", "后包围", "侧面"]
  imageCount: number;          // 3
  products?: BodyKitProduct[]; // 仅 CMST 来源有产品明细
}

export interface BodyKitProduct {
  productId: string;           // "CMST-BW-P01-R01"
  category: string;            // "前唇"
  productName: string;         // "极氪001前唇"
  years: string;               // "2024-2025"
  materials: string[];         // ["ABS"]
  process: string[];           // ["吸塑"]
  colors: string[];            // ["亮黑", "哑黑"]
  seriesName: string;          // 系列名
  imageCount: number;
}
```

⚠️ **两套部件命名需归一**：CMST 用「前唇/后唇/侧裙/整套/尾翼」（产品件），BSKT 用「前包围/后包围/侧面」（视角）。建议**对外统一用「前唇 / 后唇 / 侧裙 / 尾翼 / 整套」**，把 BSKT 的「前包围→前唇、后包围→后唇、侧面→侧裙」映射过去。
