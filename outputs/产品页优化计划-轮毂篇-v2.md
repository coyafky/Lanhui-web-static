**数据转换要点**：
1. JSON 中 `编号_原始` 含源Sheet名（"奔驰"、"宝马"等）→ 可直接提取车型品牌
2. `规格汇总.尺寸` 数组 → 拆分为具体尺寸筛选值
3. `明细` 每行有独立规格/PCD/ET/CB/颜色/库存 → 作为 SKU 列表
4. 图片命名与编号对应（TJ02001.png, AUDI001.png）→ 建立编号→图片映射
5. ⚠️ JSON 有 UTF-8 BOM，解析时需 `encoding='utf-8-sig'`

## 四、关键技术决策

### 4.1 数据格式：用 JSON 还是 Markdown？

**推荐：用 JSON**（`旋压轮毂数据.json` / `锻造轮毂XX数据.json`）

理由：
- JSON 已结构化（明细数组、规格汇总），解析成本低
- Markdown 是 JSON 的渲染版，信息等价但需正则提取
- JSON 含 `编号_原始`（源Sheet=车型品牌），Markdown 没有
- JSON 有 `解析核对.csv` 可交叉验证

### 4.2 图片命名映射规则

- 锻造：`TJ02001.png` / `TJ02001_2.png` → 编号 `TJ02001` + 序号
- 旋压：`AUDI001.png` / `AUDI001_2.png` → 编号 `AUDI001` + 序号
- 锻造(主目录)：`GZM520.png` / `GM08001.png` → 编号对应
- ⚠️ 部分编号有 `_2` `_3` 多图（最多 5 张，如 GZ085）
- ⚠️ 部分编号对应多张不同角度/颜色的图

**方案**：建立 `{编号: string[]}` 映射（编号→图片数组），按外置盘文件名扫描生成

### 4.3 产品卡片展示信息层级

```
┌─────────────────────────────┐
│  [图片]                      │
│  ┌─────────┐                │
│  │ 锻造 标签 │  18×8         │
│  └─────────┘  PCD 5×112     │
│               ET 35 | CB 66.5│
│  黑色车面 枪灰车面           │
│  库存: 有货                  │
└─────────────────────────────┘
```

### 4.4 统一数据模型

```typescript
export type WheelProcess = "锻造" | "旋压";
export type WheelBrand = "奥迪" | "宝马" | "奔驰" | "保时捷" | "大众" | "特斯拉" | "小米" | "理想" | "蔚来" | "问界" | "丰田" | "日产" | "路虎" | "凌志" | "通用";

export interface WheelSku {
  size: string;        // "18*8"
  pcd: string;         // "5*112"
  et: string;          // "35"
  cb: string;          // "66.5"
  color: string;       // "黑色车面"
  stock: number;       // 32
  note?: string;       // "短螺丝"
}

export interface WheelProduct {
  id: string;          // "TJ02001"
  process: WheelProcess;
  brand: WheelBrand | "通用";
  images: string[];    // ["/images/products/wheel/TJ02001.png", ...]
  sizes: string[];     // ["18*8", "18*9", "19*8.5"]（去重排序）
  pcds: string[];      // ["5*112"]（去重）
  ets: string[];       // ["35", "45"]（去重排序）
  cbs: string[];       // ["66.5"]（去重）
  colors: string[];    // ["枪灰车面", "黑色车面"]
  skus: WheelSku[];    // 全量明细
  totalStock: number;  // 总库存
}
```
